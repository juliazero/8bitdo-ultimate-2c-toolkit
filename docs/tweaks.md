# What the tweaks do

| Tweak | Effect |
| --- | --- |
| Xbox Series X\|S controller over Bluetooth | Over Bluetooth the controller presents as an Xbox Series X\|S pad (`045e:0b13`), so macOS's GameController framework handles it natively (name "8BitDo Ultimate 2C (X/S)"). Needs a re-pair afterwards (or macOS may still detect it as a HID device). Its Bluetooth name can be your own, 1 to 27 printable ASCII characters, written to the GATT device name, the scan response and their two lengths; a new name also shows only after a re-pair. Since 1.2 it also hides the template keyboard characteristic that made macOS show the controller as a keyboard in the battery widget. |
| Rumble over Bluetooth | Rumble works over Bluetooth (the original firmware switches the motors off in that mode). Needs the Xbox tweak as it uses its profile. In rare cases it could make the controller stop responding. This hasn't been observed. |
| Long rumble over Bluetooth | An Xbox rumble request gives a duration of at most 2.55 s and a loop count: the duration, then loop-count times more. Rumble over Bluetooth ignores the loop count, and Android's driver for the Xbox pad (hid-microsoft) sends a long rumble once, with the longest duration and loop count, and nothing more until the strength changes, so on Android a long rumble stopped after 2.55 s. With this tweak the loop count is honoured as on an Xbox controller: duration × (loop count + 1), at most 652.8 s. The next request, the controller's own buzzes and a disconnection end it sooner; the start delay is still ignored. macOS repeats requests every 2 s through SDL, so it didn't need this. A wrapper around the rumble handler, two calls in the stock motor setter, and 108 bytes in the stock Report Map, which the Xbox tweak leaves unused; it doesn't use the Home ring's code. Off by default. Needs Rumble over Bluetooth. |
| Xbox 360 controller over cable | Plugged in by cable it presents as a wired Xbox 360 pad (`045e:028e`), which Apple's own driver takes. It changes the least code of all the tweaks. By cable the controller calls itself "8BitDo Ultimate 2C Wireless Controller", the dongle's name too, because its "8BitDo Ultimate 2C Wired Controller" (`0x179f4`) is for the battery-less 2C Wired, chosen at `0xe902` only when the battery reads 1999 mV or less at power-on. If you choose a name, such as "8BitDo Ultimate 2C (Wired)", this tweak also rewrites that product string (`0x1792c`) and the length it's sent with (`0xe91c`); otherwise it leaves 8BitDo's. Reinstalling keeps a name chosen before. |
| Dimmer LEDs | Slightly lowers the brightness of the controller's three lights, by giving them weak drive strength. It is subtle: to really change the ring around the Home button, use Home Ring in the Settings tab. |
| Battery alerts | The ring blinks slowly while charging and quickly at 6 % or less (about 2 hours left on the controller the table was measured on), even if you turned it off. The motors give one short pulse when charging starts, one long pulse when it completes, and two short pulses at 1 % (about 30 minutes), again every 5 minutes. Up to 1.1 the alerts came at 15 % and 5 % of the original percentage, many hours before the end; reinstalling brings the new ones. Needs the Home ring's code. |
| Controller settings | Adds what the Settings tab changes. Needs the Home ring's code. |
| Fixes | Moving a stick counts as using the controller, which the original firmware only notices through buttons, so playing only with sticks no longer turns it off after 15 minutes. A dropped connection gets its full search time. Unplugging the cable in the Bluetooth position restarts the controller, so it finds the Mac at once. It also closes the firmware update over Bluetooth, which needs no encryption. Needs the Home ring's code. |
| Processor rest | Over Bluetooth on battery, the original firmware keeps the processor busy in a loop. This stops it for up to 1 ms at a time between radio events, woken by the radio, the system timer or its own 1 ms timer. This may make the battery last longer. A watchdog restarts the controller if the main loop ever stops for 3 s. Since 1.1 it also keeps the battery log ([diagnostics.md](diagnostics.md)). On by default. Needs the Home ring's code. |
| Finer stick movement | The firmware ignores stick changes of up to 20 of about 4,000 steps, which makes slow movement advance in small jumps. This lowers that threshold to 14, just above the noise measured on one controller, and reads the sticks twice per report. A stick held still away from the centre may still move by one step now and then. Off by default. Needs the Home ring's code. |
| Faster button reading | The firmware reads the buttons and triggers every 5 ms. This reads them every 2.5 ms, so a press arrives about 1.25 ms sooner on average. The time Home must be held and turbo's rate are rescaled to stay the same. About 100 fast taps on one controller showed no double presses, but the firmware has no other debounce, so a worn button could bounce. Off by default. |
| Faster Bluetooth input | The controller asks for a 7.5 ms connection interval, the shortest Bluetooth LE allows, instead of the 12.5 ms every install asks for, still with no peripheral latency. An Android TV (kernel 5.15) follows it: input arrives every 7.5 ms instead of every 12.5 ms. macOS keeps its own 15 ms, and the controller works normally there with it. The controller wakes for every exchange, so the battery runs down sooner. Off by default. |
| Battery level | Included in every install, with no switch: the percentage comes from a table measured on one controller, used mostly over Bluetooth with little rumble, from a full charge until it turned itself off. It follows the time that was left on that controller. The original firmware maps 3499-4100 mV evenly: on the same controller it showed 50 % with 72 % of the time left, and 1 % for the last 7 hours. Other controllers, and games that vibrate a lot, may give somewhat different times. |
| Bluetooth connection request | Included in every install, with no switch: the controller asks for a 12.5 ms connection interval with no peripheral latency, instead of 7.5 ms with latency 59, or 7.5 ms with no latency with Faster Bluetooth input. macOS refuses any such request from a gamepad and keeps 15 ms; Linux and Windows may follow it. |
| Home ring | The code that drives the ring around the Home button, installed with any tweak that needs it. Its level is set in the Settings tab or with L4 + R4: normal, 25 %, 5 %, 1 %, 0.1 % or off (the percentage is PWM duty, not perceived brightness). It still blinks while searching or pairing, at its usual brightness, and settles at your level once connected. Installing keeps the ring's level as it is. |

Each tweak is a hash-checked set of byte edits to the original firmware 1.09; nothing else in the firmware changes, and the controller's bootloader, MAC, calibration and pairings are never written. See [SAFEGUARDS.md](../SAFEGUARDS.md) for every check the app makes.

## The dongle's tweaks

| Tweak | Effect |
|---|---|
| Xbox 360 controller over 2.4 GHz | With the controller connected through it, the dongle presents as a wired Xbox 360 pad (`045e:028e`, class `ff`), which Apple's own driver takes, at up to 1,000 reports a second. Its bcdDevice becomes `0x0103` instead of `0x0114`, so the app can tell a paired dongle from the controller by cable without reading it; Apple's driver matches on vendor, product and interface class only. 9 bytes of its X-input device descriptor. Its name in X-input, the product string at `0xf144` and the length the handler at `0xdbb4` sends it with (`0xdbc4`), stays 8BitDo's unless you choose a name, such as "8BitDo Ultimate 2C (Xbox 360)" (1 to 38 printable ASCII characters); a dongle installed with 8BitDo's name there is still recognised. |
| D-input mode with B + Home | The dongle's first firmware, 1.00, came up as a D-input gamepad (`2dc8:301c`, one HID interface) when the controller marked its packets `0x8f`, which it does once it's set to D-input. 1.03 kept that mode, its descriptors and its reports, but always comes up as X-input. This puts the check back: the link-up handler (RAM code, image `0x6940`) calls `link_mode` (`firmware-src/dongle.s`, 60 bytes in the zeros after the image at `0xff48`) instead of `init_usb_xinput`, which goes to D-input for `0x8f` with 1.00's conditions and to X-input otherwise. Android handles the D-input gamepad natively, so it suits an Android TV without Xbox controller support. To set it, with the controller on and its cable unplugged, hold B and Home until it turns off, then keep holding B and press Home to turn it on; turning it on from off with B + Home leaves it in X-input. X and Home held turns it off and back to X-input. Checked by running the dongle's own code in an emulator, and tested on hardware. In D-input the dongle can also have its own name, if you choose one, such as "8BitDo Ultimate 2C (D-input)" (1 to 36 characters); otherwise it keeps the X-input name, as 1.03 does. 1.03 sends the same name in both modes, and another (`0xf508`) only for the Wukong edition (`0x84305e == 2`); a chosen D-input name makes the check `cmp mode, #1` instead (`0xdbbc`, 6 bytes), so D-input gets the string at `0xf508`, which holds the name, with its length at `0xdbd4`. A Wukong edition dongle then has the X-input name in X-input. Checked by running the handler in an emulator. A dongle installed before names, with 8BitDo's bytes there, is still recognised. |

### Verified Steam mapping and 2.4 GHz battery telemetry

The following options are separate, selectable tweaks. Their internal keys and firmware edits are unchanged by the UI reorganization.

| Device | Tweak key | Purpose / requirement |
| --- | --- | --- |
| Controller | `usb_dinput_steam` | Wired Bluetooth-style Steam DInput report mapping, including L4/R4; requires `usb_dinput`. Verified on physical hardware. |
| Dongle | `dongle_dinput_steam` | 2.4 GHz DInput report and HID layout plus PID `2dc8:301b`; requires `dongle_dinput`. Verified with Steam and physical hardware on Windows. Idle PID stays `2dc8:301c`; XInput PID stays `2dc8:310a`. |
| Controller | `rf_battery_tx` | Sends an eight-byte battery trailer with the 2.4 GHz input packet; verified on Windows in XInput and DInput. Linux/macOS detection is untested. |
| Dongle | `dongle_rf_tail` | Captures all 28 RF payload bytes in the diagnostic buffer. |
| Dongle | `dongle_rf_read` | Exposes that buffer to Toolkit diagnostics in DInput and XInput; tested on Windows. Linux/macOS access to the vendor HID interface still needs verification. |

Battery telemetry needs the controller transmit tweak and both dongle receive/read tweaks. The three tweaks remain independently selectable so that existing recognized firmware combinations are not changed or migrated automatically. The Toolkit can show **Unrecognized firmware** for unknown firmware images; it does not silently reinterpret them.

The controller's own firmware 1.09 does the switching, unchanged: with the cable unplugged, hold B and Home until it turns off, then hold B while you press Home to turn it on. It then asks for D-input every time it connects over 2.4 GHz, until you turn it off with X and Home held. In D-input mode the dongle is detected while the controller is connected, but firmware modifications require switching the controller off first.

The app puts the dongle in update mode by itself whenever it writes; [SAFEGUARDS.md](../SAFEGUARDS.md) describes how it checks and writes the dongle. With the controller connected through the dongle, the app reads the dongle but changes nothing. The controller's own firmware can only be read by cable.
